## Goal
A 30-minute safety-net sync per active athlete that catches missed webhooks and late edits.

## Context
- `docs/architecture.md` → §5 Incremental sync.

## Scope
1. `src/trainsync/sync/incremental.py` — `incremental_sync(ctx, athlete_id)`:
   `after = max(start_date) - 2 days` (or full backfill if the athlete has no activities and no
   succeeded backfill); paginate `after=…&page=N&per_page=200` until empty; same upsert path;
   record a `sync_runs` row with `kind=incremental`.
2. `schedule_incremental(ctx)` cron job every 30 minutes (`arq.cron`, minute `{0, 30}`) that
   enqueues `incremental_sync` for each `active` athlete with job id
   `incremental:{athlete_id}:{window}` so overlapping cron runs don't double-enqueue.
3. Skip athletes with a backfill still `running`/`paused`.
4. Priority: incremental counts as **low** priority for the budget (same as backfill).

## Out of scope
Webhooks (Phase 3).

## Acceptance criteria
- [ ] An activity edited in fake_strava 1 day ago (via `/_control/activities`) is updated by incremental sync (integration test).
- [ ] An activity uploaded with an old `start_date` inside the 2-day window is picked up (test).
- [ ] Cron enqueues exactly one job per active athlete per window; inactive athletes and athletes mid-backfill are skipped (test).
