## Goal
"Give me a 4-day upper/lower hypertrophy program for a gym with barbells and dumbbells" produces a
sensible program, the next session's weights are suggested automatically, and the app tells you
which plates to load.

## Scope
1. `src/trainsync/modules/training/generator.py` — deterministic, rule-based (no LLM):
   templates full-body (2–3 days), upper/lower (4), push/pull/legs (3 or 6); inputs
   `days_per_week`, `goal`, `equipment[]`, `session_minutes`; picks exercises from the library
   by movement pattern and available equipment; sets/reps by goal
   (strength 3–5 × 3–6, rest 180 s; hypertrophy 3–4 × 8–12, rest 90 s; general 3 × 8–12, rest 75 s);
   trims accessories to fit `session_minutes`. `POST /v1/training/programs/generate` (preview) and
   save.
2. `progression.py` — double progression: when every working set of an exercise hit `rep_max`
   last session → suggest +2.5 kg (lower body +5 kg, configurable); if two sessions in a row miss
   `rep_min` → suggest −10 % (deload). Suggestions returned when a workout starts.
3. `plates.py` — `plates_per_side(target_kg, bar_kg=20, inventory={25:2,20:2,15:2,10:2,5:2,2.5:2,1.25:2})`
   → per-side list or nearest lower achievable weight with the difference; inventory counts are
   per pair. Settings: `GYM_BAR_KG`, `GYM_PLATES` (e.g. `25x2,20x2,…`). `GET /v1/training/plates?target=…`.
4. ADR (next free number): "Rule-based programs; LLM optional on top".

## Acceptance criteria
- [ ] Generator: every template × goal × equipment combo produces a valid program within the time budget; same input → same output (property-style test).
- [ ] Progression rules on fixtures (hit, miss once, miss twice → deload).
- [ ] Plates: exact, unreachable (nearest lower + diff), inventory limits, bar heavier than target (tests).
