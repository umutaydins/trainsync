## Goal
A real worker process with shared resources and an idempotent activity repository that every sync
path (backfill, incremental, webhooks) will reuse.

## Context
- `docs/architecture.md` → Components (worker), Data model (`activities`), §4–§6 share one upsert path.
- `docs/phases/phase-2-sync.md` → tasks 1 and 3.

## Scope
1. `src/trainsync/worker.py` — `WorkerSettings` with `on_startup`/`on_shutdown` that create and
   close: settings, DB engine + sessionmaker, Redis, the shared `httpx.AsyncClient`, `TokenManager`
   and `StravaClient`; store them in `ctx`. A typed accessor (`WorkerContext` dataclass) so job
   functions don't dig through `dict[str, Any]`. Sensible `max_jobs`, `job_timeout`, `max_tries`.
2. `src/trainsync/db/repositories/activities.py` — `ActivityRepository.upsert_many(athlete_id,
   activities: Sequence[StravaActivity]) -> int` using
   `INSERT … ON CONFLICT (strava_activity_id) DO UPDATE SET …, synced_at = now()` with a `WHERE`
   clause that skips rows whose data didn't change (compare `raw`), returning the number of rows
   actually inserted/updated. `soft_delete(strava_activity_id)`, `delete_for_athlete(athlete_id)`,
   `max_start_date(athlete_id)`.
3. Mapping `StravaActivity → row`: `distance → distance_m`, `moving_time → moving_time_s`,
   `elapsed_time → elapsed_time_s`, `total_elevation_gain → elevation_gain_m`, full JSON → `raw`.
   A re-created activity that was soft-deleted gets `deleted_at = NULL`.
4. ADR (next free number): "arq instead of Celery" — asyncio-native, Redis already required,
   small footprint; trade-offs (fewer features, no built-in priorities).

## Out of scope
Backfill/incremental logic (P2.2/P2.3).

## Acceptance criteria
- [ ] Worker starts with `arq trainsync.worker.WorkerSettings` against testcontainers and shuts down cleanly closing all resources (integration test).
- [ ] Upserting the same 200 activities twice: first returns 200, second returns 0 and no row changes `synced_at` (integration test).
- [ ] Changing one field upserts exactly one row (test).
- [ ] Soft-deleted activity is restored by a later upsert (test).
