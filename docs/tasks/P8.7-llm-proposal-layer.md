## Goal
When `ANTHROPIC_API_KEY` is set, the model can suggest program changes in natural language terms
and explain any proposal; it can never apply anything the rule layer would reject.

## Scope
1. Tools for the model: read training/body/nutrition summaries; `propose_changes(changes[])`
   whose input schema is the same typed change list as P8.5.
2. Every LLM-proposed change is validated by the rules (allowed exercises/equipment, volume
   bounds, guard rails); invalid ones are dropped with the reason recorded.
3. "Explain this proposal" endpoint and bot button produce a short explanation grounded in the
   proposal's numbers.
4. Disabled cleanly without a key (feature flag); no test calls the real API.

## Acceptance criteria
- [ ] Scripted fake model: valid changes become a `source=llm` proposal; invalid ones are rejected with reasons (tests).
- [ ] Without a key, endpoints return a clear "disabled" response; the weekly rule engine is unaffected (test).
