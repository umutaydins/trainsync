## Goal
`StravaClient` always has a valid access token: tokens are stored encrypted, refreshed 5 minutes
before expiry or once after a 401, and concurrent refreshes for the same athlete never race.

## Context
- `docs/architecture.md` → §2 Token refresh (read it fully — the lock rationale matters).
- Strava rotates refresh tokens: the response to a refresh may contain a different
  `refresh_token`; the old one becomes invalid. Always persist what Strava returns.
- `TokenCipher` (P1.3), `StravaClient.refresh` + `token_provider` protocol (P1.5), models (P1.2).

## Scope
1. `src/trainsync/modules/strava/token_repository.py` — `TokenRepository`: `get(athlete_id)`,
   `upsert(athlete_id, access, refresh, expires_at, scope)` (encrypts on write, decrypts on read),
   `delete(athlete_id)`. Upsert uses `INSERT … ON CONFLICT (athlete_id) DO UPDATE`.
2. `src/trainsync/modules/strava/tokens.py` — `TokenManager` implementing the `token_provider` protocol:
   - `access_token(athlete_id)`: load tokens; if `expires_at - 5 min <= now` → refresh under lock.
   - `force_refresh(athlete_id)`: used after a 401.
   - Lock: Redis `SET token-refresh:{athlete_id} <uuid> NX PX 15000`; release with a Lua
     compare-and-delete script (only the owner releases). A caller that doesn't get the lock waits
     (poll with small injected sleep, bounded to ~10 s), then **re-reads tokens from the DB** — if
     another holder already refreshed, it uses the new token without calling Strava.
   - Inside the lock: re-read tokens first (double-checked), refresh only if still needed.
3. Wire 401 handling into `StravaClient`: on 401 → `force_refresh` once → retry the request once →
   on a second 401 raise `StravaAuthError` (the athlete probably revoked access).
4. ADR (next free number): "Redis lock for token refresh" — why a DB row lock / in-process lock is
   not enough (API + worker are separate processes; multiple workers).

## Out of scope
OAuth endpoints (P1.7).

## Acceptance criteria
- [ ] Tokens in the DB are ciphertext; repository round-trip returns plaintext (integration test).
- [ ] Token valid for > 5 min → no refresh; valid for < 5 min → exactly one refresh (unit test, injected clock).
- [ ] **Race:** two concurrent `access_token()` calls for the same expiring athlete → exactly one `POST /oauth/token` and both get the same new token (integration test with real Redis, respx or fake_strava counting calls).
- [ ] Rotated refresh token from Strava is persisted; the old one is never used again (test).
- [ ] 401 → one refresh + one retry; 401 again → `StravaAuthError`, total 2 API calls + 1 refresh (test).
- [ ] Lock is released on exceptions; a lock held by someone else is never deleted by us (test).
