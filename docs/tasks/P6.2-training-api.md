## Goal
Typed endpoints to manage programs and log workouts from a phone over unreliable networks.

## Scope
1. Under `/v1/training` (API key like the rest of `/v1`):
   - exercises: list/search (`q`, `muscle`, `equipment`), create custom, update custom;
   - programs: CRUD, activate (only one active), get with days and exercises;
   - workouts: start (optionally from a program day → returns the planned exercises with the
     last performance of each: last sets' reps × weight), get, finish, delete, list (keyset);
   - sets: `PUT /v1/training/workouts/{id}/sets/{client_id}` — **idempotent upsert by
     client-generated UUID** (retries and double taps never duplicate), delete by client_id;
   - progress: `GET /exercises/{id}/progress` (e1RM and best set per session over time),
     `GET /volume/weekly` (per muscle), `GET /prs`;
   - body metrics: put by date, list.
2. Validation: weight 0–500 kg in 0.25 steps, reps 0–100, rest ≥ 0; finishing an empty workout is allowed.
3. OpenAPI examples; regenerate `docs/openapi.json` and web types.
4. ADR (next free number): "Client-generated ids for idempotent set logging".

## Acceptance criteria
- [ ] Same `PUT` twice (and concurrently) → one row, second returns 200 with the same body (integration test).
- [ ] Starting from a program day returns planned exercises with last performance (test).
- [ ] Progress endpoints match P6.1 math on a seeded history (test).
