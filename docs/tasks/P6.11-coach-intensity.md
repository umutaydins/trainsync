## Goal
In the hardcore tone the coach gets much harder and speaks up at the right moments: before and
at a scheduled workout, when it is skipped, at workout start, when a rest is over, and at the
end with a verdict. The owner opts into an unrestricted "savage" intensity; a handful of hard
guardrails (body, slurs, pain/injury, calorie pressure) hold in every intensity.

## Context
- Message packs per tone × language and the neutral nutrition layer (ADR 0016, P6.8); the
  assistant system prompt (ADR 0014); programs, workouts, sets, suggestions (ADR 0017, 0018);
  the daily check-in flow and its scheduler (ADR 0020); the `notifications` idempotency table
  (ADR 0012); `CHECKIN_TZ` as the owner's local day.

## Scope
1. **Intensity.** `BOT_INTENSITY=normal|savage` (default `normal`). `savage` is the owner's
   explicit opt-in: no profanity limit (the heaviest Turkish swearing, brutal roasting of excuses
   and missed work), in the coach lines and in the assistant. It applies with `BOT_TONE=hardcore`;
   `BOT_LANG=en` falls back to the hardcore English pack. The assistant system prompt states the
   user explicitly asked for this tone. `/yumusak` turns on a soft mode for 24 h (normal
   intensity), `/sert` ends it; the state is a Redis key shared by bot and worker.
2. **Roast triggers** (savage, tr):
   - excuses in chat ("canım istemiyor", "yarın yaparım", "bu hafta gitmeyeceğim", …): call the
     excuse out hard, then one concrete next action for today (today's program day and start
     time, or a fallback);
   - underperformance, compared with the program and recent history: a logged set below the
     planned reps or the suggested weight; a workout finished with planned sets missing; a
     scheduled workout skipped; a check-in "skipped" without a reason;
   - food: never shame eating. The line is "eat it, log it, stay in your daily target"; never
     "burn it off" or punishment exercise. Food replies use the neutral layer.
3. **Timed messages** (worker; `notifications` table for idempotency; local time `CHECKIN_TZ`):
   - program days get an optional `weekday` and `start_time` (migration). Days without a weekday
     follow a default spread by `days_per_week`; a missing start time uses `WORKOUT_REMINDER_TIME`;
   - reminders 30 min before, at start, nudges at +30 and +90 min, a "missed" message at +180 min
     if still no workout was started that local day; each stops as soon as a workout starts;
   - workout start line, a "rest is over" line (`completed_at + rest_seconds` of the last set, if
     no newer set was logged), a summary + verdict at finish (PRs praised, misses roasted), and an
     "under target" line once per exercise per workout;
   - quiet hours (`QUIET_HOURS=23:00-07:00` default): no proactive coach message is sent then.
4. **Packs.** A savage/tr pack with ≥ 60 original lines across `excuse`, `missed_workout`,
   `under_target`, `workout_start`, `rest_over`, `workout_done_good`, `workout_done_bad`,
   `reminder_before`, `reminder_now`, `escalation`, plus `punchline_en` (≥ 20 short original
   English lines, appended to about 1 in 4 savage messages). Rotation never repeats the last 10
   lines of a category. Optional git-ignored `config/messages.local.yaml` (same categories) is
   merged in and sent verbatim; `config/messages.local.example.yaml` is committed.
5. **Guardrails** (the only limits in savage; code + assistant prompt; tested): roast the excuse
   or the effort, never body, weight or appearance; no slurs on ethnicity, religion, sexual
   orientation, disability or similar; pain, injury, illness, dizziness, chest pain → no roast,
   rest / see a doctor, no push; no calorie-restriction pressure below the nutrition target.
   Profanity itself is never filtered.
6. **Bug** (2026-10-18: the assistant said "Senkronize edilmiş veri yok (last_synced_at boş)"):
   check that a completed backfill sets `last_synced_at` everywhere the assistant reads it, and
   that the assistant does not call a running first sync "no data". Regression test.

## Out of scope
Push notifications other than Telegram; web UI for weekdays/start times (the API accepts them;
the web builder keeps the defaults); an English savage pack.

## Acceptance criteria
- [ ] Unit tests: trigger detection, rotation (no repeat of the last 10), punchline appending,
      local override merge, quiet hours, soft mode, guardrails (an injury message never gets a
      roast; no pack or local line roasts body/weight/appearance or uses a slur; no calorie
      pressure lines).
- [ ] Integration test: the reminder cron with a fake clock (before, now, +30, +90, missed;
      stops when a workout starts; nothing in quiet hours; never twice).
- [ ] Regression test for `last_synced_at` after a backfill, through the API and the assistant's tools.
- [ ] ADR for the intensity model and the guardrails; `.env.example`, `operations.md` updated.
