## Goal
The two clients get everything they need from `/v1` without reaching into the database.

## Context
- Existing read API: `src/trainsync/api/activities.py`, `stats.py`, `sync_status.py`,
  `db/repositories/reads.py`. Same rules: API key, `last_synced_at` in responses, OpenAPI examples.

## Scope
1. `GET /v1/activities/{strava_activity_id}` → one activity (404 if unknown or soft-deleted);
   `?include=raw` like the list endpoint.
2. `GET /v1/stats/summary?from=&to=&sport_type=` → totals for the range (`count`, `distance_m`,
   `moving_time_s`, `elevation_gain_m`) plus the same totals grouped by `sport_type`, and the
   longest activity in the range. One SQL query per block, no Python-side aggregation.
3. Update `docs/openapi.json` (export script) and the OpenAPI completeness test.

## Out of scope
Any UI or bot code.

## Acceptance criteria
- [ ] Detail endpoint: 200 / 404 (unknown) / 404 (soft-deleted) / 401 without key (tests).
- [ ] Summary matches a hand-computed fixture, including the by-sport breakdown and an empty range (integration test).
- [ ] `docs/openapi.json` is current; completeness test passes.
