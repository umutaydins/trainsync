## Goal
When Strava is failing, stop hammering it: open the circuit, delay jobs, probe with a single
request after a cooldown, and recover automatically.

## Context
- `docs/architecture.md` → §3 Circuit breaker, Failure-modes table.

## Scope
1. `src/trainsync/strava/breaker.py` — per-process `CircuitBreaker(failure_threshold=5,
   cooldown=30 s, clock)` with states `closed → open → half_open → closed|open`.
   Failures: 5xx and timeouts/transport errors **after** retries are exhausted. 4xx and 429 are
   not breaker failures. Exactly one probe in `half_open` (asyncio lock); others get
   `CircuitOpen(retry_at)` immediately.
2. Integrate in `StravaClient` before each logical call; expose `state` for metrics/status.
3. Jobs: `CircuitOpen` → re-enqueue self with `_defer_until=retry_at` (+ small jitter), don't
   count as a failed try; backfill marks run `paused`.
4. ADR (next free number): "Per-process circuit breaker" — vs a shared Redis breaker; trade-offs.

## Acceptance criteria
- [ ] State-machine unit tests: threshold, cooldown, single probe, probe success closes, probe failure reopens.
- [ ] 4xx/429 never open the circuit (test).
- [ ] With fake_strava `ERROR_RATE=0.5`, the circuit opens, jobs are delayed (not failed), and after setting `ERROR_RATE=0` all 1,000 activities arrive exactly once (integration test).
