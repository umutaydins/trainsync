## Goal
Every stored event ends in the correct final state, regardless of duplicates or ordering.

## Context
- `docs/architecture.md` → §6 Worker processing, Failure-modes table.

## Scope
1. `src/trainsync/modules/sync/webhooks.py` — job `process_webhook_event(ctx, event_id)`:
   - claim the row: `UPDATE … SET status='processing', attempts=attempts+1 WHERE id=:id AND status IN ('pending','failed')`; if nothing claimed → return (already processed).
   - `activity create|update` → `get_activity(object_id, priority="high")` → upsert. **Use the
     fetched state, not the event.** `StravaNotFound` → treat as deleted (soft delete).
   - `activity delete` → soft delete (idempotent; deleting an unknown activity is fine).
   - `athlete update` with `updates.authorized == "false"` → in one transaction: `active=false`,
     delete tokens, delete the athlete's activities. Later events for that athlete are marked
     processed without fetching.
   - unknown `owner_id` → processed (ignored) with a log line.
   - success → `status=processed`, `processed_at`; `RateLimited`/`CircuitOpen` → back to `pending`
     and re-enqueue deferred; other errors → `status=failed`.
2. Out-of-order safety: if an activity is soft-deleted and a later-processed `update` fetches
   404, it stays deleted; if fetch succeeds after a delete event (activity re-created in fake),
   trust the fetch.
3. ADR (next free number): "Fetch current state on every activity event".

## Acceptance criteria
- [ ] create → update → delete delivered **out of order** ends with the activity soft-deleted (integration test via P3.2 scenario).
- [ ] create + update delivered in reverse order ends with the latest title (test).
- [ ] Duplicate events are processed once (fetch count via fake stats) (test).
- [ ] Deauthorization removes tokens and activities and deactivates the athlete (integration test).
- [ ] Webhook fetches still run while backfill is paused by the budget (test).
