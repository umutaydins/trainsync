## Goal
The owner switches the bot between Turkish and English from the chat, without a redeploy. Every
message (replies, check-in, coach reminders and workout lines, alerts, errors, the assistant)
follows the chosen language; `BOT_LANG` is only the default.

## Context
- Message packs per tone × language and the neutral layer (ADR 0016, P6.8); the savage pack,
  `punchline_en`, the local lines file and the guardrails (ADR 0030, P6.11); the worker's timed
  messages (check-in ADR 0020, coach ADR 0030, stack alerts ADR 0027).
- The bot process has no database access: it reads and writes through the API (ADR 0013).

## Scope
1. **`/lang`** shows two inline buttons, "Türkçe" and "English"; `/lang tr` and `/lang en`
   switch directly; anything else gets a usage line.
2. **Storage.** A `chat_settings` table (`chat_id` PK, `lang` `en|tr`, `updated_at`; migration
   0011) behind `GET/PUT /v1/chats/{chat_id}/settings`. No row = `BOT_LANG`. It survives restarts
   and redeploys; the bot caches the value per process.
3. **Everything follows the language.** The bot sets the language per update; pack messages,
   check-in questions, errors, coach lines and the assistant's system prompt ("Reply in …") use
   it. Command names and the help text stay English in both languages.
4. **Packs.** Every tone has a pack in both languages (neutral/en, neutral/tr, hardcore/en,
   hardcore/tr) with every key; a savage/en pack (≥ 60 original lines, the same categories and
   guardrails as savage/tr, unlimited profanity). `punchline_en` is appended in both languages.
   Savage now works with `BOT_LANG=en` too.
5. **Local lines.** `config/messages.local.yaml` takes a `tr:` and an `en:` section plus a
   top-level `punchline_en` (both languages). The first format (categories at the top level)
   still works and counts as Turkish.
6. **Worker.** Reminders, nudges, workout lines, the check-in prompt, new-activity notifications
   and stack alerts read the stored language at send time.
7. **Confirmation** after switching: in the new language and the current intensity's tone (a
   savage `language_set` line in savage mode).

## Out of scope
More languages; per-chat tone or intensity; a language switch in the web dashboard; the host
uptime check (`ops/uptime.py`, outside the worker) stays English.

## Acceptance criteria
- [x] Language persistence (API + database, across a restart) and the default fallback to
      `BOT_LANG` (also when the API cannot be reached).
- [x] A test that fails when a pack is missing a key or a category: every tone in both languages,
      both savage packs with every category.
- [x] The assistant receives the chat's language; a worker message is sent in the stored
      language.
- [x] ADR, `operations.md`, task spec, snapshot tests updated.
