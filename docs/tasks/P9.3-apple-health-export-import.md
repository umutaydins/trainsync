## Goal
Backfill years of weight, body fat and activity history from the Health app's "Export All Health
Data" file.

## Scope
1. Upload goes **directly to the API**, not through the web BFF (exports are often hundreds of
   MB and serverless functions have small body limits): the web asks the API for a one-time
   upload URL (`POST /v1/health/imports` → `{import_id, upload_url, expires_at}`), the browser
   streams the file to it; the API writes to a temp volume.
2. Worker job parses `apple_health_export/export.xml` with a streaming parser (`iterparse`,
   clearing elements) — never loads the file into memory; only `HKQuantityTypeIdentifierBodyMass`,
   `BodyFatPercentage`, `LeanBodyMass`, `Height`, `RestingHeartRate`, `StepCount`,
   `ActiveEnergyBurned` (configurable list); unit conversion (lb → kg, % scale); batched upserts
   through the P9.1/P9.2 dedup path.
3. `health_imports` table: status, counts per type, error, started/finished; progress endpoint;
   temp file deleted after processing; max size setting.
4. Defend against zip bombs and path traversal (check sizes and member names before extracting).
5. Gateway (P7.1): raise the request size limit for the upload route only; extend `prod-check`.
   Verify the browser on Vercel uploads to the backend URL, not the Vercel domain.

## Acceptance criteria
- [ ] Generated 100k-record export imports with peak RSS under a bound (test measures).
- [ ] Re-importing the same export inserts nothing new (test).
- [ ] Malicious zip (traversal, huge expansion) rejected (tests).
