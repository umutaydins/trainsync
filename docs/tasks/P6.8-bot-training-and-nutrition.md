## Goal
Quick logging and answers from Telegram when opening the web app is too slow.

## Scope
1. `/today` — today's planned program day with suggested weights; `/plates 102.5` — per side.
2. `/log bench 80x5x3` (exercise alias, weight × reps × sets; adds to today's open workout or
   starts one) and `/done` (finish, summary with volume and PRs).
3. `/eat <food> <grams>` (matches favourites/recent by name; ambiguous → numbered choices),
   `/kcal` (today's intake vs target, macros), `/weight 78.4` (body metric).
4. Uses the read/write API through the bot's API client (no DB access); idempotent client ids.
5. Tone: training messages follow `BOT_TONE`/`BOT_LANG` message packs if present;
   **nutrition and body-weight messages are neutral in every tone** (test asserts the
   hardcore pack has no nutrition/body keys and the blocklist test covers new texts).

## Acceptance criteria
- [ ] Parser tests for `/log` and `/eat` (valid, invalid, ambiguous).
- [ ] Handler tests with the fake Telegram API and stubbed trainsync API.
- [ ] Repeated `/log` delivery (Telegram retry) creates one set (test).
