## Goal
A production stack definition that is safe to expose: secrets out of the repo, internal services
private, and a single gateway that only forwards the routes the outside world needs.

## Scope
1. `compose.prod.yml`: api, worker, bot, postgres, redis, gateway (Caddy) with
   `restart: unless-stopped`, healthchecks, memory limits, named volumes; Postgres/Redis on an
   internal network with no published ports; images tagged by git SHA.
2. Secrets from `.env.prod` (git-ignored) with `.env.prod.example`; startup fails fast on missing values.
3. Caddy gateway on `127.0.0.1:8080` (Funnel terminates TLS): path allowlist —
   `/webhooks/strava*`, `/auth/strava/*`, `/v1/*`, `/health/*`;
   everything else 404 (incl. `/metrics`, `/docs` unless `EXPOSE_DOCS=true`); security headers;
   request size limits; per-IP rate limit on `/auth/*`. The route allowlist and per-route limits live
   in one place with a test, so later phases (Phase 8 import upload) add exceptions there.
4. `make prod-check`: renders config, verifies no published DB/Redis ports and the allowlist (curl matrix).

## Acceptance criteria
- [ ] `make prod-check` passes; requests to non-allowlisted paths return 404 (scripted test in CI using the prod compose with dummy secrets).
- [ ] Missing secret → container exits with a clear message (test).

## Verify
```
make verify
make prod-check
```
