## Goal
All tables from the architecture exist via an Alembic migration, the app has an async session
factory, and `/health/ready` reports DB + Redis reachability.

## Context
- `docs/architecture.md` → Data model (tables, columns, indexes) and §8.
- Settings from P1.1 (`DATABASE_URL`, `REDIS_URL`).

## Scope
1. `src/trainsync/modules/*/models.py` — SQLAlchemy 2.0 typed declarative models (`Mapped[...]`,
   `mapped_column`) for `athletes`, `oauth_tokens`, `activities`, `sync_runs`, `webhook_events`,
   exactly as in the data-model table:
   - all timestamps `TIMESTAMP WITH TIME ZONE`, stored in UTC;
   - `activities.raw`, `sync_runs.cursor`, `webhook_events.payload` are `JSONB`;
   - `sync_runs.kind` (`backfill`/`incremental`) and `status` (`running`/`succeeded`/`failed`/`paused`),
     `webhook_events.status` (`pending`/`processing`/`processed`/`failed`) as string enums with
     CHECK constraints (native PG enums make migrations painful — note this in the ADR below);
   - unique constraints: `athletes.strava_athlete_id`, `activities.strava_activity_id`,
     `webhook_events.dedup_key`;
   - indexes: `activities (athlete_id, start_date DESC)`,
     `activities (athlete_id, sport_type, start_date)`, `webhook_events (status, received_at)`;
   - `oauth_tokens.athlete_id` is PK and FK → `athletes.id` `ON DELETE CASCADE`;
     `activities.athlete_id` FK → `athletes.id` `ON DELETE CASCADE`.
2. `src/trainsync/core/db.py` — `create_engine(settings)`, `async_sessionmaker`, a FastAPI
   dependency yielding `AsyncSession`. Engine created/disposed in the app lifespan.
3. Alembic in `migrations/` configured for async (`env.py` reads `DATABASE_URL` from Settings),
   first revision `0001_initial` created with autogenerate and then reviewed by hand.
   `alembic upgrade head` and `alembic downgrade base` both work.
4. Redis client (`redis.asyncio`) created in the lifespan, stored on `app.state`.
5. `GET /health/ready` → `200 {"status":"ok","db":"ok","redis":"ok"}` when `SELECT 1` and
   `PING` succeed (each with a 1 s timeout); otherwise `503` with the failing component marked
   `"error"`. Never leaks exception text containing connection strings.
6. `tests/integration/conftest.py` — session-scoped testcontainers fixtures: Postgres 16
   (`postgres:16-alpine`), Redis 7 (`redis:7-alpine`); runs `alembic upgrade head` once; a
   function-scoped fixture that truncates all tables between tests. Mark the module
   `pytestmark = pytest.mark.integration`.
7. ADR (next free number in `docs/decisions/`): "String enums with CHECK constraints instead of
   native Postgres enums".

## Out of scope
Repositories / upsert logic (P2.1), token encryption (P1.3).

## Acceptance criteria
- [ ] Migration upgrade → downgrade → upgrade round-trip succeeds on a real Postgres (integration test).
- [ ] Autogenerate after `upgrade head` produces no diff (integration test using `alembic.autogenerate.compare_metadata`).
- [ ] Unique constraints and FK cascades behave as specified (integration test: deleting an athlete removes its tokens and activities).
- [ ] `/health/ready` returns 200 with both containers up and 503 when Redis is unreachable (test).
- [ ] Integration tests run under `make test-integration` and are skipped from `make test-unit`.
