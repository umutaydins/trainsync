## Goal
One clean model for everything the scale and the user report about the body, with a noise-free
trend that charts, goals and the adaptive engines can rely on.

## Scope
1. Migration: `body_measurements` (`id`, `measured_at` timestamptz, `kind` weight/body_fat_pct/
   lean_mass_kg/height_cm/bmi/resting_hr, `value` numeric, `unit`, `source`
   manual/apple_health/apple_health_export/checkin, `source_name` (e.g. "Xiaomi Home"),
   `dedup_key` unique, `created_at`). Migrate existing `body_metrics` rows (kind=weight,
   source=manual) and keep a read-compatible view or update callers (check-ins, bot `/weight`).
2. `dedup_key = sha256(kind|measured_at rounded to the second|value rounded|source_name)`.
3. Trend weight (pure function): exponential moving average with α = 0.1 over daily weights
   (latest per day, gaps carried forward without inventing points), plus 7-day and 28-day change.
   Lean mass derived as `weight × (1 − bf%)` when only weight and body fat exist for the same
   measurement time (± 5 min).
4. `goals` (`kind` weight/body_fat_pct/e1rm/weekly_volume/running_km, `target`, `target_date`,
   `exercise_id` nullable, `active`); progress = linear projection from the trend.
5. API: `/v1/body/measurements` (list by kind/range, idempotent `PUT` by dedup key, delete),
   `/v1/body/trend`, `/v1/goals` CRUD + progress.

## Acceptance criteria
- [ ] Migration keeps all existing weights (integration test).
- [ ] Trend/EMA, weekly change, lean-mass derivation and goal projection match a fixture.
- [ ] Same measurement twice → one row (test).
