## Goal
Log what you eat in seconds and see intake against targets and estimated expenditure.

## Scope
1. Migration + models: `foods` (`id`, `name`, `brand`, `barcode` unique nullable, `kcal_100g`,
   `protein_100g`, `carbs_100g`, `fat_100g`, `source` manual/openfoodfacts, `favorite`),
   `food_logs` (`id`, `client_id` uuid unique, `date`, `meal` breakfast/lunch/dinner/snack,
   `food_id`, `grams`, `created_at`), `nutrition_profile` single row (`sex`, `birth_year`,
   `height_cm`, `activity_baseline` sedentary/light/moderate, `kcal_target`, `protein_target_g`).
2. `/v1/nutrition`: foods search/create/update/favorite; optional lookup by barcode or name in
   Open Food Facts (public API, no key, custom User-Agent, 3 s timeout, results cached in `foods`;
   tests use a fake via respx); food log idempotent `PUT` by client_id, delete, list by date;
   profile get/put; summary `GET /summary?date=` and `GET /summary/weekly?from=&to=`.
3. Energy balance (pure functions, documented as estimates):
   - BMR Mifflin–St Jeor: male `10w + 6.25h − 5a + 5`, female `… − 161`, weight = latest `body_metrics`;
   - baseline multiplier (1.2 / 1.375 / 1.55) applied to BMR **excluding** logged exercise;
   - exercise kcal from synced activities: `raw.calories` when present (detailed activity),
     else cycling `raw.kilojoules` ≈ kcal, else `null` (shown as "unknown", never guessed);
   - balance = intake − (baseline + exercise).
4. Guard rails: a `kcal_target` below BMR is accepted but returned with a `warning` field;
   no automatic aggressive deficit suggestions.

## Acceptance criteria
- [ ] Summaries and energy balance match a hand-computed fixture (integration test).
- [ ] Same food-log `PUT` twice → one row (test).
- [ ] Open Food Facts lookup works against the fake and degrades gracefully on timeout (test).
