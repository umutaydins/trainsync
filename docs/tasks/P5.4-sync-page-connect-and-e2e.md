## Goal
The owner can see whether sync is healthy and connect an account from the UI, and the whole
flow is proven end to end against the compose stack.

## Scope
1. `/sync`: data from `/v1/sync/status` — last backfill/incremental runs, webhook
   pending/failed/dead-letter counts, rate-limit usage bars (15-min and daily), circuit state per
   process (badge colours), auto-refresh every 15 s.
2. "Connect Strava" button → API `/auth/strava/login` (public base URL from env); after the
   callback the user lands back on `/sync` (add a `return_to` allowlisted redirect to the API
   callback if needed, with a test there).
3. Playwright e2e (`web/e2e/`) against `docker compose up` with fake_strava: log in → connect
   via the fake OAuth → wait for backfill → dashboard KPI totals equal `/v1/stats/summary`
   fetched directly → open an activity → sync page shows a succeeded backfill.
   `make web-e2e`; CI job that runs it after the compose job.

## Acceptance criteria
- [ ] e2e passes locally and in CI.
- [ ] Open redirect impossible: `return_to` outside the allowlist is ignored (backend test).

## Verify
```
make verify
make web-verify
make web-e2e
```
