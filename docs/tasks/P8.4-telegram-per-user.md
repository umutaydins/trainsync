## Goal
Every user links their own Telegram chat; the bot answers each chat with that user's data.

## Context
ADR 0036, ADR 0012/0013 (the bot is an API client).

## Scope
1. `telegram_chats` (chat id → user, one per user); migration links `TELEGRAM_ALLOWED_CHAT_IDS`
   to the owner.
2. `POST /v1/me/telegram/code` (Redis, TTL), `DELETE /v1/me/telegram`,
   `GET /v1/telegram/chats/{chat_id}`, `POST /v1/telegram/chats/{chat_id}/link`,
   `DELETE /v1/telegram/chats/{chat_id}` (service key only).
3. Bot: `/link CODE`, `/unlink`; an unknown chat gets only the link hint; every call carries
   `X-Acting-User`; a one-minute cache of chat → user.
4. `SERVICE_API_KEYS`: only those keys may send `X-Acting-User`.

## Acceptance criteria
- [ ] Unknown chats get the hint and nothing else; `/link` with a used or expired code fails.
- [ ] Two linked chats see their own data; `/unlink` stops answers at once.
- [ ] A non-service key with `X-Acting-User` is refused (403).

## Verify
`make verify`
