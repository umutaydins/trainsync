## Goal
In the gym, on a phone, one hand: see what to do, log a set in two taps, rest with a timer,
know which plates to load.

## Scope
1. `/training/programs`: generate from the form (days, goal, equipment, minutes) → preview → save;
   edit days/exercises (reorder, sets, reps, rest); activate.
2. `/training/workout/[id]` (mobile-first, large touch targets):
   - list of planned exercises; each set row shows last time's reps × weight and the suggested
     weight (progression); tap ✓ to log (optimistic UI, `PUT` with a client uuid, retry on failure);
   - **workout timer** (elapsed since start) and **rest timer** that starts automatically after
     a set with the exercise's `rest_seconds`, +15 s / −15 s / skip, vibration + sound + optional
     Notification at zero;
   - timers are **timestamp-based** (store `endsAt`, render `endsAt − now`), so they stay correct
     when the tab is backgrounded or the screen locks; state survives a reload (localStorage);
   - **plate calculator** sheet for barbell exercises (from `/v1/training/plates`), drawn as a bar
     with coloured plates per side;
   - Screen Wake Lock API while a workout is active (graceful fallback);
   - finish → summary (duration, total volume, PRs hit).
3. PWA: manifest, icons, theme colour, installable on iOS/Android home screen. Offline logging is
   out of scope (note it as a follow-up), but failed `PUT`s are retried from a local queue on reconnect.

## Acceptance criteria
- [ ] Timer logic unit-tested with fake timers incl. "backgrounded for 3 minutes" and reload restore.
- [ ] Double-tap ✓ produces one set (component test + API idempotency).
- [ ] Plate drawing matches the API answer (component test).
- [ ] Usable at 375 px width; axe check passes.
