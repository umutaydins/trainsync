## Goal
A standalone FastAPI app that behaves like the parts of Strava we use, including rate-limit
headers, 429s, latency and errors, so dev, integration tests and load tests never touch the real API.

## Context
- `docs/architecture.md` → Components (fake_strava), §3 rate limits.
- Real Strava behaviour to imitate:
  - `GET /oauth/authorize?client_id&redirect_uri&response_type=code&scope&state&approval_prompt`
    → in the fake: immediately `302` to `redirect_uri?code=<code>&state=<state>&scope=<scope>`.
  - `POST /oauth/token` (form fields `client_id`, `client_secret`, `grant_type`, and `code` or
    `refresh_token`). Response JSON:
    `{"token_type":"Bearer","access_token":"…","refresh_token":"…","expires_at":<unix>,"expires_in":21600,"athlete":{"id":…,"firstname":…,"lastname":…}}`
    (the `athlete` object only for `authorization_code`). Refresh may return a **new** refresh token.
  - `GET /api/v3/athlete` → `{"id":…,"firstname":…,"lastname":…}`.
  - `GET /api/v3/athlete/activities?before=<unix>&after=<unix>&page=<n>&per_page=<≤200>` →
    list sorted by `start_date` desc, empty list after the last page.
  - `GET /api/v3/activities/{id}` → one activity or `404 {"message":"Record Not Found"}`.
  - Activity JSON fields used: `id`, `name`, `sport_type`, `start_date` (ISO-8601 UTC, `Z`),
    `distance` (m, float), `moving_time` (s), `elapsed_time` (s), `total_elevation_gain` (m),
    `average_heartrate` (optional float).
  - Every API response carries `X-RateLimit-Limit: 200,2000` and `X-RateLimit-Usage: <15min>,<daily>`
    (and the read-specific `X-ReadRateLimit-Limit/Usage` pair, same format). 15-minute windows
    reset on the quarter hour (UTC :00/:15/:30/:45), daily at 00:00 UTC. Over budget → `429`.
  - Missing/invalid bearer token → `401 {"message":"Authorization Error"}`.

## Scope
1. `fake_strava/` package (`app.py`, `state.py`, `seed.py`) with `create_app(config)`; runnable as
   `uv run uvicorn fake_strava.app:create_app --factory --port 8001`.
2. In-memory state: one or more athletes, seeded deterministic activities
   (`FAKE_STRAVA_SEED_ACTIVITIES`, default 300, fixed RNG seed), issued tokens with expiry.
3. Config via env (prefix `FAKE_STRAVA_`): `LATENCY_MS` (default 0), `ERROR_RATE` (0.0–1.0, returns
   random `500/502/503`), `RATE_LIMIT_15MIN` (200), `RATE_LIMIT_DAILY` (2000),
   `TOKEN_TTL_S` (21600), `SEED_ACTIVITIES`, `RNG_SEED`.
4. Control endpoints under `/_control` (not part of Strava) for tests: `POST /_control/config`
   (change any config at runtime), `POST /_control/reset`, `GET /_control/stats` (request counts
   by endpoint and status), `POST /_control/activities` (create/update/delete an activity to
   simulate athlete edits), `POST /_control/expire-tokens`.
5. An injectable clock so tests can move time forward to cross a 15-minute window.
6. A pytest fixture in `tests/conftest.py` that serves fake_strava in-process via
   `httpx.ASGITransport` (unit level) — the docker service comes in P1.8.
7. Add `fake_strava` to ruff and mypy targets (`[tool.mypy] files`).

## Out of scope
Webhook firing (P3.2). The trainsync Strava client (P1.5).

## Acceptance criteria
- [ ] Full OAuth code → token → refresh flow works against the fake, and refresh rotates the refresh token (test).
- [ ] Pagination: 300 seeded activities with `per_page=200` → pages of 200, 100, then `[]`; `before`/`after` filters work (test).
- [ ] Rate-limit headers are present and usage increments; exceeding the 15-minute budget returns 429 until the clock crosses the next quarter hour (test with injected clock).
- [ ] `ERROR_RATE=1.0` makes every API call return 5xx; `0.0` none (test).
- [ ] Expired or unknown bearer → 401 (test).
- [ ] Seed is deterministic: same seed → identical activity list (test).
