## Goal
A `web/` Next.js app that can call the trainsync API safely: the API key stays on the server,
and only the owner can open the dashboard.

## Context
- The read API authenticates with `X-API-Key` (ADR on keyset pagination and API key in README).
- Single user. No public sign-up.

## Scope
1. `web/`: current stable Next.js with App Router, TypeScript strict, Tailwind, ESLint, pnpm.
   Vitest + Testing Library for unit tests.
2. BFF: route handler `web/app/api/ts/[...path]/route.ts` that forwards **GET only** to an
   allowlist of `/v1/*` paths, adds `X-API-Key` from `TRAINSYNC_API_KEY` (server env), passes
   query strings through, maps upstream errors to `{error}` JSON with the same status. Server
   components call a typed `lib/api.ts` client that uses the same function directly.
   Response types generated from `docs/openapi.json` with `openapi-typescript` (script
   `pnpm gen:api`, output committed; a test fails if it is stale).
3. Access gate: `middleware.ts` requires a session cookie; `/login` checks `DASHBOARD_PASSWORD`
   (constant-time compare) and sets an `httpOnly`, `secure` (in prod), `sameSite=lax` signed
   cookie (`DASHBOARD_SESSION_SECRET`, 7 days). Logout route.
4. `make web-verify` = `pnpm install --frozen-lockfile && pnpm lint && pnpm typecheck && pnpm test && pnpm build`
   (run in `web/`). Add a `web` job to `.github/workflows/ci.yml`.
5. `web/Dockerfile` (multi-stage, `output: "standalone"`, non-root) and a `web` service in
   `docker-compose.yml` on port 3000, pointing at `http://api:8000`. Env vars documented in
   `.env.example`.
6. ADR (next free number): "Server-side BFF instead of calling the API from the browser".

## Out of scope
Real pages beyond a placeholder home and the login page.

## Acceptance criteria
- [ ] Without a session, every page redirects to `/login`; wrong password → 401; right password → cookie and redirect (tests).
- [ ] BFF rejects non-GET and non-allowlisted paths (tests) and adds the API key server-side.
- [ ] `TRAINSYNC_API_KEY` does not appear in any file under `.next/static` after `pnpm build` (test/script in `web-verify`).
- [ ] `make web-verify` green locally and in CI; `make compose-smoke` still passes with the `web` service.

## Verify
```
make verify
make web-verify
make compose-smoke
```
