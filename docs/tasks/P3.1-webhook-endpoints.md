## Goal
Strava can validate our subscription, and every event is acknowledged in well under 2 seconds after
being persisted (deduplicated) and enqueued — no Strava calls in the handler.

## Context
- `docs/architecture.md` → §6 Webhooks.
- Strava specifics:
  - Validation: `GET /webhooks/strava?hub.mode=subscribe&hub.challenge=<str>&hub.verify_token=<str>`
    → `200 {"hub.challenge": "<str>"}` (JSON, exact key with the dot).
  - Event POST body: `{"object_type":"activity"|"athlete","object_id":int,"aspect_type":"create"|"update"|"delete","updates":{…},"owner_id":int,"subscription_id":int,"event_time":int}`.
    Deauthorization is `object_type=athlete, aspect_type=update, updates={"authorized":"false"}`.
  - Strava expects `200` within 2 s and retries a few times otherwise.

## Scope
1. `src/trainsync/modules/sync/webhook_router.py`:
   - GET: check `hub.mode == "subscribe"` and constant-time compare of `hub.verify_token`;
     403 otherwise.
   - POST: validate with a pydantic model; if `STRAVA_WEBHOOK_SUBSCRIPTION_ID` is set and doesn't
     match → `200` but ignore (log a warning; don't make Strava retry). Compute
     `dedup_key = sha256(f"{subscription_id}:{object_type}:{object_id}:{aspect_type}:{event_time}")`.
     `INSERT … ON CONFLICT (dedup_key) DO NOTHING RETURNING id`; only when a row was inserted,
     enqueue `process_webhook_event(event_id)` with job id `webhook:{event_id}`. Always `200`.
   - Malformed JSON → `400` (Strava won't send it; protects against junk).
2. ADR (next free number): "Acknowledge, persist, then process webhooks".

## Out of scope
Processing (P3.3), the fake sender (P3.2).

## Acceptance criteria
- [ ] Validation echoes the challenge for the right token and returns 403 for a wrong one (test).
- [ ] Posting the same event 5 times stores 1 row and enqueues 1 job (integration test).
- [ ] The handler makes zero outbound HTTP calls (test with respx `assert_all_mocked` / no routes).
- [ ] p99 latency < 100 ms over 300 sequential POSTs against testcontainers (integration test; record the measured value in the test output).
