## Goal
Ask the bot "how was my week?" and get a correct answer in seconds, from anywhere.

## Context
- Telegram Bot API; long polling (`getUpdates`) so no public URL is needed.
- Use `aiogram` 3.x (asyncio-native) or plain httpx — decide in an ADR.

## Scope
1. `src/trainsync/entrypoints/bot/`: `main.py` entry point (`python -m trainsync.entrypoints.bot`), handlers, message
   formatting module (pure functions), and a small client for the trainsync read API
   (httpx, `X-API-Key`, reusing the response models) — the bot does not touch the DB directly.
2. Commands: `/start` (help), `/week` (this ISO week vs last week), `/last` (latest activity),
   `/stats [4w|12w|52w] [sport]` (summary + best week), `/status` (sync health in one line).
3. Settings: `TELEGRAM_BOT_TOKEN` (SecretStr), `TELEGRAM_ALLOWED_CHAT_IDS` (comma list),
   `BOT_API_BASE_URL`. Messages from other chats get no reply and a log line (no token/ids logged
   beyond the chat id).
4. Graceful shutdown, backoff on Telegram 429/5xx (honour `retry_after`), structured logs,
   a `bot_updates_total{command,outcome}` metric on its own port.
5. Compose service `bot` (same image, `python -m trainsync.entrypoints.bot`), disabled when the token is empty.
6. ADR (next free number): "Telegram first, behind a Notifier interface" (why not WhatsApp yet:
   Business verification, templates, per-conversation cost, public webhook).

## Acceptance criteria
- [ ] Formatting functions unit-tested against fixtures (numbers, units, empty week).
- [ ] Handler tests with a fake Telegram API (respx): allowlisted chat gets the reply, others get nothing.
- [ ] `/week` numbers equal `/v1/stats/summary` for the same range (integration test with the API in-process).
- [ ] Telegram 429 with `retry_after` is honoured without a busy loop (test with injected sleep).
