## Goal
Real, reproducible throughput and latency numbers for the webhook POST and the read API, recorded
in the README.

## Scope
1. `loadtest/locustfile.py` — two user classes: `WebhookSender` (POST realistic events, ~10%
   duplicates) and `ApiReader` (`/v1/activities` with pagination, `/v1/stats/weekly`), API key
   from env.
2. `make loadtest` — starts the compose stack (with fake_strava seeded with 5,000 activities and a
   finished backfill), runs locust headless for a fixed duration (e.g. 2 min, 50 users, spawn
   rate 10) with `--csv loadtest/results/run`, tears the stack down.
3. `scripts/loadtest_summary.py` turns the CSV into a markdown table (RPS, p50/p95/p99, error %).
4. Add a manually triggered workflow `.github/workflows/loadtest.yml` (`workflow_dispatch`) that
   runs `make loadtest` and uploads the CSV + summary as an artifact.
5. README → "Load test results": the table from an actual run, plus machine description
   (e.g. GitHub-hosted `ubuntu-latest`, 4 vCPU) and date. No placeholders.

## Acceptance criteria
- [ ] `make loadtest` runs end to end and produces the CSV and summary.
- [ ] README contains measured numbers from a real run and how to reproduce them.
- [ ] Webhook POST p99 meets the Phase 3 target (< 100 ms) under the documented load, or the README explains the measured value honestly.

## Verify
```
make verify
make loadtest
```
