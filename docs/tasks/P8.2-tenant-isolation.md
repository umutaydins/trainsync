## Goal
Every user-owned row belongs to one user and no request can read or write another user's rows.

## Context
ADR 0035. All tables were single-user (nutrition profile `id = 1`, body metrics keyed by date).

## Scope
1. Migration 0016: `user_id` on athletes, oauth_tokens, activities, sync_runs, programs,
   program_days, program_exercises, workouts, workout_sets, body_metrics, daily_checkins,
   food_logs, nutrition_profile, notifications; nullable `user_id` on exercises and foods
   (null = shared); `food_favorites`; per-user unique constraints; owner from `OWNER_EMAIL`
   when data exists; `chat_settings` → `user_settings`; guarded, idempotent, reversible.
2. Every repository takes `user_id`; every router uses `CurrentUser`.
3. IDOR suite generated from the OpenAPI document.
4. Migration test on seeded single-user data (upgrade, re-run, downgrade, upgrade).

## Acceptance criteria
- [ ] User B gets 404 on every one of user A's ids; lists never contain A's rows.
- [ ] Two users can use the same client id and the same dates without touching each other.
- [ ] Seeded single-user data ends up owned by the owner; downgrade restores it.

## Verify
`make verify`, `make restore-check-ci`
