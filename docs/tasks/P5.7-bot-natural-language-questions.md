## Goal
"How many km did I run in September compared to August?" gets a correct, grounded answer:
the model only decides which read-API calls to make; every number comes from the API.

## Scope
1. `src/trainsync/bot/assistant.py`: Anthropic Python SDK, model from `ASSISTANT_MODEL` env,
   disabled when `ANTHROPIC_API_KEY` is empty. Tools mapped 1:1 to read endpoints:
   `get_summary(from, to, sport_type?)`, `get_weekly(from, to, sport_type?)`,
   `list_activities(from?, to?, sport_type?, limit)`, `get_sync_status()`. Strict JSON schemas,
   date validation, max 5 tool calls per question, 20 s total timeout.
2. System prompt: answer only from tool results, say when data is missing or stale
   (`last_synced_at`), metric units, reply in the user's language.
3. Plain messages (not commands) from allowlisted chats go to the assistant; commands stay deterministic.
4. Cost/abuse guard: per-chat rate limit (e.g. 20 questions/hour) in Redis.
5. ADR (next free number): "LLM as a planner over the read API, never as a data source".

## Acceptance criteria
- [ ] Unit tests with a scripted fake Anthropic client: tool calls are executed against a stubbed API and the final text contains the API numbers.
- [ ] Invalid tool arguments are rejected and reported back to the model, not executed (test).
- [ ] Tool-call limit and timeout enforced (tests); rate limit enforced (test).
- [ ] No test calls the real Anthropic API.
