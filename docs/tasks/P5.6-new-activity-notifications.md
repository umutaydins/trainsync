## Goal
When a new activity arrives via webhook, the owner gets exactly one short message.

## Scope
1. `src/trainsync/modules/notifications/`: `Notifier` protocol (`async send(chat_ref, text)`), `TelegramNotifier`,
   and a `NullNotifier` (default when not configured). A WhatsApp implementation is out of scope;
   the interface must make it a drop-in later.
2. After `process_webhook_event` upserts an activity for an `activity create` event, enqueue
   `notify_new_activity(strava_activity_id)` (job id `notify:{id}`).
3. Idempotency: table `notifications` (`kind`, `object_id`, `sent_at`, unique `(kind, object_id)`),
   migration 0004. Insert-then-send; on send failure, delete the row and let arq retry with
   backoff (max 5); never two messages for one activity.
4. Message: name, sport emoji, distance, moving time, pace/speed, elevation, link to the
   dashboard detail page (`DASHBOARD_PUBLIC_URL`).
5. Do not notify for backfill/incremental upserts (history), only for live `create` events.

## Acceptance criteria
- [ ] Duplicate webhook delivery → one notification (integration test with fake Telegram).
- [ ] Backfill of 1,000 activities → zero notifications (test).
- [ ] Telegram down → retried, then succeeds once; still exactly one message (fault test).
