## Goal
Once a week the app reviews training data and proposes concrete program changes with a reason
for each; nothing changes until the owner approves (except opt-in minor changes).

## Scope
1. `proposals` (`id`, `kind` program/nutrition, `program_id`, `payload` = list of typed changes,
   `reasons` list, `status` pending/approved/rejected/expired/applied, `created_at`, `decided_at`,
   `source` rules/llm). Approving applies via P9.4 (new version, `change_source=engine`).
2. Rules (pure, each with a stable id and unit tests), evaluated over the last 3–4 weeks:
   - stalled lift: no e1RM gain in 3 exposures at the same load → swap to a listed variation or
     change rep range (e.g. 5×5 → 4×8), keep movement pattern;
   - regression + high RPE (≥ 9 average) or two missed `rep_min` → deload week (−10 % load, −1 set);
   - low adherence (< 60 % of planned days in check-ins for 2 weeks) → propose fewer days
     (regenerate with `days_per_week − 1`) or shorter sessions;
   - consistent overperformance (all sets ≥ rep_max + 2) → bigger increment;
   - goal-driven: weight-loss goal + strength dropping fast → reduce volume, keep intensity;
     strength goal on a hypertrophy template → propose template switch;
   - weekly volume per muscle outside 6–24 sets → rebalance accessories.
3. Weekly cron (Sunday 20:00 local) creates at most one pending proposal per program;
   older pending ones expire.
4. Setting `AUTO_APPLY_MINOR=false` (default). "Minor" = load increments/decrements ≤ 5 % and rest
   changes; everything else always needs approval.
5. API: list/get proposals, approve (optionally a subset of changes), reject with note.

## Acceptance criteria
- [ ] Each rule triggers on its fixture and stays silent on a control fixture (tests).
- [ ] Approve applies exactly the selected changes as one new version; reject changes nothing (tests).
- [ ] Auto-apply only for minor changes and only when enabled (tests).
