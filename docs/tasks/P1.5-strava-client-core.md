## Goal
The single module that talks to Strava, with explicit timeouts, a correct retry policy and
rate-limit header parsing — fully unit-tested with respx.

## Context
- `CLAUDE.md` → Rules (only `strava/client.py` imports httpx for Strava; one shared AsyncClient).
- `docs/architecture.md` → §3 Strava client.
- Header formats are documented in `docs/tasks/P1.4-fake-strava.md` → Context.

## Scope
1. `src/trainsync/core/http.py` — `build_http_client(settings) -> httpx.AsyncClient` with
   `httpx.Timeout(connect=3, read=10, write=10, pool=5)` and pool limits; created in the app
   lifespan (and later the worker), closed on shutdown.
2. `src/trainsync/integrations/strava/retry.py`
   - `RetryPolicy(max_attempts=4, base=0.5 s, cap=8 s)`;
     `backoff(attempt, rng) -> float` = **full jitter**: `uniform(0, min(cap, base * 2**attempt))`.
   - `is_retryable(response | exception) -> bool`: retry on `httpx.TransportError`/timeouts, 5xx and
     429; never on other 4xx (401 is handled separately by P1.6).
   - A `sleep` callable is injected so tests don't actually sleep.
3. `src/trainsync/integrations/strava/ratelimit.py`
   - `parse_rate_limit(headers) -> RateLimitSnapshot | None` reading `X-RateLimit-Limit/Usage` and,
     when present, `X-ReadRateLimit-Limit/Usage` (`"<15min>,<daily>"`); tolerant of missing or
     malformed headers (returns `None`, logs a warning once).
   - `RateLimitSnapshot` exposes `short_ratio`, `daily_ratio` (max of overall and read limits).
   - `next_window_reset(now) -> datetime` — next UTC quarter hour; `next_daily_reset(now)` — next 00:00 UTC.
4. `src/trainsync/integrations/strava/client.py` — `StravaClient(http, settings, token_provider, policy, clock, sleep)`
   - Methods: `get_athlete()`, `list_activities(*, before, after, page, per_page)`,
     `get_activity(activity_id)`, plus OAuth `exchange_code(code)` and `refresh(refresh_token)`
     (these hit `STRAVA_OAUTH_BASE_URL`).
   - `token_provider` is a protocol `async def access_token(athlete_id) -> str` (P1.6 implements it;
     use a stub here).
   - On every response: parse rate-limit headers and hand the snapshot to an injected
     `on_rate_limit` callback (P2.4 stores it in Redis).
   - On 429: do not retry immediately — raise `RateLimited(reset_at=next_window_reset(now))`
     (the caller/job decides to wait; P2.4).
   - Typed results: pydantic models `StravaAthlete`, `StravaActivity`, `TokenResponse`.
   - Raises typed errors: `StravaNotFound`, `StravaAuthError`, `StravaUnavailable`
     (retries exhausted), `RateLimited`.
5. Structured log line per call: endpoint template (e.g. `/activities/{id}`, never the full URL with
   ids/tokens), status, duration_ms, attempt. Never log headers.

## Out of scope
Token storage/refresh/locking (P1.6), Redis budget (P2.4), circuit breaker (P2.5), metrics (P4.1).

## Acceptance criteria
- [ ] Backoff values always fall in `[0, min(cap, base·2^attempt)]` over many samples, and the upper bound grows then caps (property-style test).
- [ ] Retries happen for timeouts, connect errors, 500/502/503/504; not for 400/403/404/422 (parametrized respx test counting calls).
- [ ] After `max_attempts` failures `StravaUnavailable` is raised and exactly 4 requests were made.
- [ ] 429 raises `RateLimited` with `reset_at` = next quarter hour and makes no extra requests.
- [ ] Rate-limit parsing: normal, read-limit headers, missing, malformed (`"abc"`, `"1"`) cases (test).
- [ ] Response JSON maps into the typed models, including missing `average_heartrate` (test).
- [ ] No module other than `strava/` imports `httpx` for Strava calls (a test greps `src/`).
