## Goal
The web app can call the new write endpoints without exposing the API key or opening CSRF holes.

## Scope
1. Extend the BFF allowlist with method + path rules: GET for read paths, and
   POST/PUT/DELETE only for `/v1/training/**` and `/v1/nutrition/**`.
2. CSRF: mutations require same-origin `Origin` (or `Referer`) matching `DASHBOARD_PUBLIC_URL`
   **and** a double-submit token (`csrf` cookie + `X-CSRF-Token` header). Session cookie stays
   `sameSite=lax`, httpOnly.
3. Request body size limit (64 KB) and JSON-only content type on mutations.
4. Regenerate `web/lib/api-types.ts`; update ADR 0011 with the write rules.

## Acceptance criteria
- [ ] Mutation without/with wrong Origin or token → 403; correct → forwarded with API key (tests).
- [ ] Non-allowlisted method/path combos rejected (table-driven test).
- [ ] Bundle check still proves the API key is not shipped to the browser.
