## Goal
Tests and load tests can make fake_strava push realistic webhook traffic at trainsync.

## Scope
1. `POST /_control/webhooks/fire` on fake_strava with body
   `{"target_url": str, "events": [Event], "mode": "single"|"duplicate"|"out_of_order", "duplicates": int, "concurrency": int}`.
   - `duplicate`: each event sent `duplicates` times (default 3) — imitates Strava retries.
   - `out_of_order`: shuffles events with a seeded RNG before sending.
   - Imitate Strava delivery: timeout 2 s; on non-200 or timeout retry up to 2 more times.
   - Returns per-event delivery results (status codes, attempts, latency).
2. Helper `POST /_control/scenario/activity-lifecycle` that mutates the fake's state AND fires the
   matching events, e.g. create → update(title) → delete for one activity, optionally out of order.
3. Typed client helper for tests in `tests/support/fake_webhooks.py`.

## Acceptance criteria
- [ ] Unit tests of the sender against a dummy ASGI target: modes, retries on 500, retry on slow target.
- [ ] Lifecycle scenario leaves fake_strava state consistent with the events it fired (test).
