## Goal
A dedicated suite (`pytest -m fault`) that proves the failure-modes table in
`docs/architecture.md`, row by row, and runs in CI.

## Scope
1. `tests/fault/` with `pytestmark = pytest.mark.fault`, one test module per failure mode:
   429 bursts, 5xx bursts, timeouts (fake latency > read timeout), duplicate webhooks,
   out-of-order webhooks, worker restart mid-backfill, token rotation under concurrency,
   deauthorization during an active backfill.
2. Each test asserts both the **outcome** (final DB state) and the **behaviour** (metrics/fake
   stats: e.g. no 429 storm, breaker opened, retries bounded).
3. Add a `fault` job to `.github/workflows/ci.yml` running `make test-fault`.
4. Add a column "Proven by" to the failure-modes table in `docs/architecture.md` linking each row
   to its test.

## Acceptance criteria
- [ ] Every row of the failure-modes table links to a passing fault test.
- [ ] `make test-fault` passes locally and in CI.
- [ ] The suite finishes in under ~5 minutes on a GitHub-hosted runner (use injected clocks, not real sleeps).

## Verify
```
make verify
make test-fault
```
