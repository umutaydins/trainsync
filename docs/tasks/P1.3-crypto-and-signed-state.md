## Goal
Small, well-tested primitives for encrypting tokens at rest and for a tamper-proof, expiring OAuth
`state` parameter.

## Context
- `CLAUDE.md` → Rules (tokens encrypted at rest, never log secrets).
- `docs/architecture.md` → §1 OAuth connect (signed `state`).

## Scope
1. `src/trainsync/core/crypto.py`
   - `class TokenCipher` built from `TOKEN_ENCRYPTION_KEY`: `encrypt(str) -> bytes`,
     `decrypt(bytes) -> str`. Use `cryptography.fernet.MultiFernet` so the env var may contain
     several comma-separated keys (first one encrypts, all decrypt) — this enables key rotation.
   - `InvalidToken` is wrapped into a project exception `TokenDecryptError` without echoing data.
2. `src/trainsync/core/state.py`
   - `sign_state(now: datetime) -> str` producing `<nonce>.<issued_at>.<hmac>` (URL-safe base64,
     HMAC-SHA256 with `STATE_SIGNING_KEY`).
   - `verify_state(value: str, now: datetime, max_age: timedelta = 10 min) -> None` raising
     `InvalidStateError` for bad format, bad signature (constant-time compare) or expiry.
   - Time is always passed in (no `datetime.now()` inside) so tests are deterministic.
3. Update `docs/architecture.md` only if behaviour differs from what is written there.

## Out of scope
Storing tokens (P1.7), refresh logic (P1.6).

## Acceptance criteria
- [ ] Encrypt → decrypt round-trip; ciphertext differs between two encryptions of the same value (test).
- [ ] Data encrypted with an old key still decrypts after a new key is prepended (rotation test).
- [ ] Tampered ciphertext raises `TokenDecryptError` (test).
- [ ] Valid state verifies; tampered nonce/timestamp/signature, wrong key and expired state all raise `InvalidStateError` (parametrized test).
- [ ] No secret or plaintext appears in exception messages (test asserts on `str(exc)`).
