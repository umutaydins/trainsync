## Goal
The dashboard signs users in against the API; the shared API key leaves user requests.

## Context
ADR 0011 (BFF), ADR 0034. The BFF had one password and sent `X-API-Key` on every call.

## Scope
1. The session cookie (httpOnly, Secure, SameSite=Lax) holds the API session token, sealed with
   `DASHBOARD_SESSION_SECRET`; server-side calls send it as `Authorization: Bearer`.
2. Route handlers: register, login, logout, me, invite accept, Telegram link code, settings,
   export, delete; CSRF stays on every mutation.
3. The proxy (middleware) protects app routes and redirects to `/login`.
4. Existing pages keep compiling; new pages come in the web UI tasks.

## Acceptance criteria
- [ ] No user request carries the API key (bundle check + tests).
- [ ] A 401 from the API clears the cookie and sends the browser to `/login`.

## Verify
`make web-verify`
